# 麦麦随心搭 combo-advisor

> 预算 + 热量双重约束下的麦当劳套餐推荐助手。
> 基于 M-China 官方 MCP 的**实时菜单、官方营养库、门店优惠券**三份数据，
> 把「今天吃什么」变成一道有约束、有依据、能解释清楚的优化题。

---

## 这个项目在解决什么

点麦当劳的真实困境从来不是「没有选项」，而是三个已知条件算不出来：

- 我今天最多花 35 块；
- 我想控制在 900 大卡以内、蛋白质最好有 25 克；
- 我还想知道能不能顺便用掉那张券。

麦当劳 MCP 已经把需要的数据全部开放了，但**三份数据互相对不上**：

| 数据源 | 有什么 | 缺什么 |
| --- | --- | --- |
| `query-meals` | 实时菜单、现价、原价、折扣类型 | 完全没有营养信息 |
| `list-nutrition-foods` | 160 道餐品的七大营养素 | 只有单品，**没有套餐**；命名与菜单不一致 |
| `query-store-coupons` | 门店可用优惠券 | —— |

于是出现了三个必须跨过去坎：

### 坎一：两套命名对不上

```
菜单里叫「薯条」      营养库里叫「中薯条」
菜单里叫「可乐」      营养库里叫「可乐中杯」
菜单里叫「纯牛奶(盒装)」 营养库里叫「纯牛奶（盒装）」   ← 半角 vs 全角括号
```

直接等号匹配，命中率不到一半。本项目用**四层递进匹配**解决：精确 → 人工别名表 → 包含关系 → 默认规格推断，并且把「用哪一招匹配上的」记下来，低置信度的项会在推荐结果里主动标注。

### 坎二：套餐没有营养数据 —— 而且容易算错

这是开发过程中踩到的**最严重的一个 bug**。

`巨无霸三件套` 里包含 `巨无霸`，于是包含关系匹配把它算成了 **513 大卡**。
真实值是巨无霸 + 中薯条 + 可乐中杯 = **949 大卡**，低估了整整 45%。
用户带着控卡的目的来点餐，拿到一个腰斩的数字，比没有数字更糟。

正确解法是调用 `query-meal-detail` 把套餐拆成子餐品再累加：

```
rounds[].choices[].isDefault == 1  →  巨无霸、中薯条、可乐中杯
```

而这些子餐品名恰好就是营养库里的标准写法。拆完逐项查表，得到 949 大卡。

为了防止这类错配复发，代码里加了 `COMBO_HINTS`：**名称里有「件套 / 套餐 / 双人餐 / 随心配」的商品，一律禁止用包含关系猜营养**，宁可报「未知」也不能猜。

> 代价是什么：营养覆盖率从表面上的 48.6% 降到 34.6%。
> 但那 14 个百分点本来就是**错配的假命中**。宁可少说，不要说错。

### 坎三：菜单里混着不是菜的东西

真实菜单里 **`麦当劳联名复古棒球帽`（¥34.9）** 和 **`韩式烟熏芝士风味酱`（¥3）** 会被当成主餐推荐出去 —— 前者是周边，后者是蘸酱。

前者靠角色识别规则剔除。后者靠一条兜底规则：**任何查不到热量的商品都不能担任主餐**——推荐出来的套餐中，这种情况不会出现。

## 快速开始

```bash
git clone <你的仓库地址>
cd mcd-combo-advisor

python3 -m combo.cli \
  --menu examples/menu-shanghai-1450713.json \
  --nutrition examples/nutrition.txt \
  --aliases combo/data/aliases.json \
  --combo-details examples/combo-details.json \
  --budget 35 --kcal-max 900 --protein-min 25 \
  --strategy balanced --top 3
```

无需安装任何依赖，只用 Python 标准库（3.9+）。`examples/` 里带的是上海黄浦某门店的真实抓取数据，不配 MCP 也能立刻跑起来。

## 参数一览

| 参数 | 说明 |
| --- | --- |
| `--budget` | **整单**总预算（元），不随人数翻倍 |
| `--people` | 人数，营养目标按人数等比放大 |
| `--kcal-min` / `--kcal-max` | 每人热量上下限（大卡） |
| `--protein-min` | 每人蛋白质下限（克） |
| `--sodium-max` | 每人钠上限（毫克） |
| `--drink` | 强制搭配饮品 |
| `--exclude 辣,牛肉` | 忌口关键字过滤 |
| `--strategy` | `balanced` / `protein` / `light` / `cheapest` |
| `--top N` | 返回几条方案 |
| `--json` | 输出结构化 JSON 供程序消费 |
| `--coverage` | 只输出营养覆盖率诊断 |

### 四种打分策略

| 策略 | 适用 | 打分逻辑 |
| --- | --- | --- |
| `balanced` | 默认，吃好吃饱 | 预算贴合度 + 省下的钱 + 蛋白质达标 + 钠超标扣分 |
| `protein` | 增肌 | 每元蛋白质最大化 |
| `light` | 减脂 | 热量越低越好，但蛋白质要保底 |
| `cheapest` | 省钱 | 摁着预算花最少 |

## 作为 WorkBuddy Skill 使用

安装 `SKILL.md` 后，不需要记任何命令，直接说话：

> 「帮我配个麦当劳套餐，预算 35，控制在 900 大卡以内」
> 「两个人的，60 块，要有喝的」
> 「我在减脂，热量别超 500」

Skill 会自动完成：定位门店 → 拉菜单 → 拉营养库 → 拆解候选套餐 → 跑引擎 → 查优惠券 → 给出带理由的方案，**并在你确认后才下单**。

## 已知限制

- **营养覆盖率不是 100%**：新品（如「龙焰」系列）尚未进官方营养库，这类餐品会标为「热量未知」并在有热量约束时被排除。这是刻意取舍，见「坎二」。
- 套餐的热量只算**默认搭配**（`isDefault=1`）。用户换成大薯条或加价换饮品时，热量会变。
- 钠超标只是提示，不做硬性拦截。
- 本工具是推荐引擎，**下单一定会先经过用户确认**。
